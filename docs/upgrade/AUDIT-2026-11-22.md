# BASM-NANO audit corrections — 2026-11-22

Baseline: `db1e36a7123d37374831433260e43cc45a01a20e`.

The fixes change the host assembler and its validation. All five guest images
remain byte-identical to the baseline. Both boot sectors remain exactly
512 bytes, including the final `55 AA` signature.

## Changes and decisions

- Hexadecimal conversion now accepts only explicit ASCII digit ranges. `@`
  and the grave accent can no longer be interpreted as digit 9.
- Register and memory MOV immediates of 16/32 bits are checked against their
  signed-value/unsigned-bit-pattern ranges. Unresolved first-pass expressions
  are checked after resolution. Shared emission primitives remain unchanged.
- Deliberate low-bit extraction for data and byte immediates is documented and
  directly covered, preserving the existing compatibility contract.
- The symbol index already enforced its 256-definition limit. Compile-time
  guards now protect its power-of-two size, maximum load and index width;
  adversarial collisions have dedicated regression coverage.
- The optional `--boot-sector` mode rejects a size other than 512 bytes or an
  incorrect signature before staging or publishing binary/map output. The
  Makefile enables it for both boot sectors and their map targets. It catches
  bytes appended after the source-level padding and signature as well.
- The generated `basm_sacred.c` was regenerated and checked for freshness.

The filesystem publication model is unchanged: the build directory must be
trusted. Replacing only the final output component with a symlink does not
redirect `rename()` into its target. Protection against hostile concurrent
directory/temporary-file replacement requires a separate threat-model change.

## Independent TCG boot smoke

QEMU 10.0.13 booted a freshly rebuilt, byte-identical `basmos.bin` with TCG.
QMP used standard input/output pipes; no network or Unix socket was needed.
The QEMU sandbox remained enabled with obsolete operations, privilege
elevation, process spawning and resource-control operations denied.

Observed results:

- VGA memory at `0xB8000`: `33 0f 36 0f 39 0a` (both tasks and IPC).
- Guest remained running; timer heartbeat advanced from 41 to 50 in 0.5 s.
- IDT: 35 entries, with the five installed handlers at their rebuilt offsets.
- `CR0=0x80000011`, `CR3=0x1000`, `CR4=0x10`, `PDE0=0xE3`.

This smoke covers the record sector. It is not a full `make verify-ci`, KVM,
shell/JASH runtime or hardware qualification claim.

## Environment limits

- The ordinary `make verify-ci` invocation was blocked when its QMP Unix
  socket could not be created (`Operation not permitted`). Its scripts and
  the environment controls were not changed. The independent stdio smoke
  above provides separate, explicitly narrower execution evidence.
- LeakSanitizer reported a fatal ptrace/environment restriction. A separate
  ASan/UBSan run with `detect_leaks=0` passed; leak freedom is not qualified.
- Clang and NASM were unavailable. The host gate ran in its explicit GCC-only
  `--quick` mode, followed by the separate GCC sanitizer run. The full CI
  compiler matrix remains unchanged and still requires its usual tools.
- `/dev/kvm` was absent. `tools/upgrade/native_gate.py` reported `BLOCKED`
  for NASM and KVM; full native proof and the optional Bear gate were not run.

These limits do not change the byte-identity evidence or the boot-sector
publication checks. They bound the additional execution claims made here.
